Introduction

Welcome to the LegalTech documentation. This guide covers everything you need to deploy and configure your installation.

LegalTech is a self-hosted SaaS platform that lets users create, sign, and manage legal contracts — powered by AI. It is built on Laravel 13 with a domain-driven architecture and ships as a pre-built, deployment-ready package.

What's included

Contract Builder
Template-based editor with rich text editing and PDF export
AI Drafting
OpenAI-powered contract generation from prompts
E-Signatures
Multi-party signing flow with signed-at timestamps
Subscriptions
Flexible plan billing — monthly, yearly, or pay-as-you-go
12 Payment Gateways
Stripe, PayPal, Razorpay, Flutterwave, and more
Admin Panel
Full control over users, contracts, CMS, settings, and analytics

What this guide covers

  • Server requirements and PHP extensions
  • Installation on cPanel and Hostinger shared hosting
  • Environment file configuration (.env)
  • Admin setup — first login, general settings, email, OpenAI
  • Payment gateway configuration for all 12 supported gateways
  • Subscription plan management
  • File storage, queue workers, and cron jobs
  • Subdirectory deployment
ℹ
No Composer or npm is required on the server. LegalTech ships as a fully compiled package — just upload, configure .env, and run migrations.

cPanel Installation

LegalTech ships as a pre-built package. No Composer or npm needed on the server.

1 — Extract files

  1. Upload the archive
    Upload legaltech.zip to your hosting via cPanel File Manager or FTP. Place it in the root of your domain (e.g. public_html/) or a subfolder (e.g. public_html/legaltech/).
  2. Extract
    Right-click → Extract in File Manager. You will see two top-level items: a Files/ folder and a README.
  3. Move contents of Files/ up
    Move everything inside Files/ to your deployment root. The result should be: public_html/assets/, public_html/index.php, public_html/src/.

Root folder brief

public_html/          ← (or subfolder like public_html/legaltech/)
├── .htaccess         ← URL rewriting, security headers, blocks .env/.log access
├── index.php         ← Entry point — routes all requests into src/
├── assets/           ← Public assets served directly by the web server
│   ├── vite/         ← Compiled JS + CSS bundles
│   ├── static/       ← Theme CSS, images, icons
│   └── uploads/      ← User-uploaded files (logos, KYC docs, etc.)
└── src/              ← Laravel application (NOT publicly accessible)
    ├── app/          ← Domain logic, controllers, models
    ├── config/       ← Laravel config files
    ├── database/     ← Migrations and seeders
    ├── resources/    ← Blade views, language files
    ├── routes/       ← Web and API routes
    ├── storage/      ← Logs, cache, queued jobs
    └── .env          ← ⬅ Your environment file goes here
⚠
The src/ directory must not be publicly accessible. Only index.php and the assets/ folder should be web-accessible. cPanel's public_html layout already satisfies this when you deploy to the domain root. For subdirectory deploys, see the Subdirectory Deploy section.

2 — Create a MySQL database

  1. Open MySQL Databases in cPanel
    Create a new database, create a new user, and assign the user to the database with All Privileges.
  2. Note credentials
    Save the database name, username, password, and host (usually localhost). You will need them for .env.

3 — Connect and migrate

  1. Edit src/.env
    Fill in your database credentials. See the Environment section below.
  2. Run migrations via SSH (recommended)
    SSH into your server, navigate to src/, then run:
cd public_html/src          # or your deployment path
php artisan migrate --seed  # creates all tables and seeds default data
💡
If SSH is unavailable, use cPanel's Terminal (Hosting > Terminal) or ask your host to run the command. Most shared hosts include Terminal in cPanel.

4 — Storage & permissions

cd src
php artisan storage:link     # not needed — uploads go to assets/uploads/ directly
chmod -R 775 storage bootstrap/cache

Ensure the web server user (usually www-data or the cPanel user) can write to src/storage/ and assets/uploads/.

Hostinger Installation

Hostinger uses hPanel instead of cPanel. The steps below map to hPanel's interface. The file structure and .env setup are identical to cPanel.

1 — Upload and extract files

  1. Open hPanel → File Manager
    Log in to hPanel, go to Hosting → Manage → File Manager, and navigate to public_html/ (or a subfolder if deploying to a subdirectory).
  2. Upload the archive
    Click Upload Files and select legaltech.zip. Wait for the upload to finish.
  3. Extract
    Right-click legaltech.zip → Extract. You will see a Files/ folder appear.
  4. Move contents up
    Select all items inside Files/, then move them to your deployment root (public_html/). The result should be: public_html/.htaccess, public_html/index.php, public_html/assets/, public_html/src/.

2 — Create a MySQL database

  1. Go to hPanel → Databases → MySQL Databases
    Create a new database and a new user. Assign the user to the database with All Privileges.
  2. Note credentials
    Save the database name, username, password, and host (usually 127.0.0.1 on Hostinger). You will need these for src/.env.

3 — Configure .env and migrate

  1. Edit src/.env via File Manager
    In hPanel File Manager navigate to public_html/src/, right-click .env.example → Copy, rename the copy to .env, then right-click → Edit to fill in your database credentials. See the Environment section for the full list.
  2. Open hPanel Terminal
    Go to hPanel → Advanced → SSH Access (or Terminal if shown). Enable SSH if not already on, then connect.
  3. Run migrations
cd ~/domains/yourdomain.com/public_html/src   # adjust path to match your domain
php artisan key:generate
php artisan migrate --seed
ℹ
On Hostinger Business / Cloud plans, SSH is included. On Starter shared plans, use the built-in Terminal in hPanel (Advanced → Terminal) — it works the same way.

4 — Storage & permissions

chmod -R 775 storage bootstrap/cache

Run this inside the src/ directory. Hostinger's web server user typically already has write access, but running this command ensures it regardless.

⚠
If your domain uses Hostinger's PHP version selector, make sure the selected PHP version is 8.3 or higher under hPanel → Advanced → PHP Configuration.

Environment File (.env)

The .env file lives at src/.env. Copy src/.env.example to src/.env and fill in the values below. Only infrastructure-level values go here — all service keys (OpenAI, mail, payment gateways, social login) are configured through Admin → Settings after installation.

Core application

APP_NAME="LegalTech"
APP_ENV=production
APP_KEY=                    # run: php artisan key:generate
APP_DEBUG=false
⚠
Always run php artisan key:generate after copying the example. Without an APP_KEY the app will not boot.

Database

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=your_database
DB_USERNAME=your_user
DB_PASSWORD=your_password
ℹ
That's all that goes in .env. OpenAI API keys, mail credentials, payment gateway keys, and social login secrets are all configured through Admin → Settings after installation — not in the environment file.

Stripe webhook

In your Stripe dashboard, create a webhook pointing to:

https://yourdomain.com/payment/webhook/stripe
# or for subfolder installs:
https://yourdomain.com/legaltech/payment/webhook/stripe

Listen for these events: checkout.session.completed, payment_intent.payment_failed. Copy the webhook signing secret (whsec_…) into the webhook_secret field in the gateway settings.

Currency settings

Each gateway has its own currency code, symbol, exchange rate, and decimal places. This lets you accept, for example, USD on Stripe and NGN on Paystack simultaneously. The exchange rate is relative to your base currency (1.0 = base).

ℹ
Credentials are stored encrypted in the database using Laravel's Crypt facade. They are never exposed in plain text via the UI.

Queue Settings → Queue

Go to Admin → Settings → Queue. When the Queue Heavy Operations toggle is enabled, bulk actions like newsletter broadcasts and mass notifications are dispatched to the database queue instead of running synchronously — keeping the admin panel responsive.

StateBehaviour
Off (default)Operations run synchronously in the same request. Fine for small volumes.
OnJobs are queued in the jobs database table. Requires the Laravel scheduler to process them — set up the cron job.
ℹ
When Queue is enabled, the settings panel shows the required cron command for your server. Copy it directly into cPanel or hPanel → Cron Jobs.

Cron Job

Add a single cron entry in cPanel under Cron Jobs. Set it to run every minute:

* * * * * cd /home/youraccount/public_html/src && php artisan schedule:run >> /dev/null 2>&1

This runs the Laravel scheduler which handles:

  • Hourly blog post publishing
  • Daily wallet reconciliation
  • Failed job pruning (7-day retention)
  • Job batch pruning (48-hour retention)
ℹ
Replace /home/youraccount/public_html/src with the actual absolute path to your src/ directory. In cPanel you can find this in File Manager → src/ → right-click → Properties.

Subdirectory Deploy

If the app is installed in a subfolder (e.g. https://yourdomain.com/legaltech/), set APP_URL to the full subfolder URL:

APP_URL=https://yourdomain.com/legaltech

The root index.php auto-detects the subfolder and adjusts all asset paths accordingly via the upload_url() helper. No extra .htaccess changes are needed beyond what ships with the package.

⚠
Do not add a trailing slash to APP_URL. Run php artisan config:clear after updating .env.
